Code signing policy

Applies to every OPBS release published on GitHub Releases, this site and the package managers that mirror them.

Status, 2026-11-11: no published build is signed yet: Get-AuthenticodeSignature on 0.6.119 returns NotSigned. OPBS's application to the SignPath Foundation programme is in preparation. This page describes the arrangement that applies once it is accepted; it is not a claim that a signed build exists today.

Signing arrangement

Free code signing provided by SignPath.io, certificate by SignPath Foundation. The certificate is issued to SignPath Foundation, so that is the publisher name shown on signed OPBS binaries.

What is signed

  • OPBS-Setup-<version>.exe — the NSIS installer.
  • OPBS-Portable-<version>.exe — the self-extracting portable build.
  • OPBS.exe and the native addon inside the installer and the portable ZIP.

The portable ZIP is a plain archive of the same signed files. Third-party binaries inside the package (Electron, Node, and the libraries in node_modules) are upstream open-source builds and are not re-signed by this project.

How a release is signed

  1. The release is built on GitHub-hosted runners from the tagged commit in bobeire/opbs. A binary built anywhere else is not signed.
  2. The unsigned artifact is uploaded to the workflow run and submitted to SignPath with origin verification, so the signature is tied to that repository, branch and commit.
  3. The signing request is approved manually before the certificate is used.
  4. SHA256 hashes of the signed files are published in the release notes. Hashes taken before signing do not apply to the published file.

Roles and members

RoleMemberResponsibility
Committer @bobeire Owns the repository and may commit to it directly.
Reviewer @bobeire Reviews every pull request from anyone who is not a committer before merge, including build scripts and CI configuration.
Approver @bobeire Approves each signing request manually. The project has a single maintainer, so this role is not separated from the others.

Verifying a download

On a signed release, PowerShell reports Valid and names SignPath Foundation as the signer:

Get-AuthenticodeSignature .\OPBS-Setup-<version>.exe | Format-List Status,SignerCertificate

Compare the SHA256 in the release notes with Get-FileHash <file> -Algorithm SHA256. An unsigned build reports NotSigned — that is accurate for every release up to and including 0.6.119, and it is not an error.

Privacy

See the privacy policy. OPBS collects no telemetry and sends nothing to RHITCS.
