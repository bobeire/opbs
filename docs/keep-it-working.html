Backups that keep working

The first backup is the easy part. What protects you is the twentieth one, taken automatically, on a Tuesday, when nothing was wrong.

The smallest routine that actually protects you

  1. One full backup, then incrementals

    A full backup captures everything. An incremental captures only what changed since the last one — so it is much smaller and much faster, and it is what makes a nightly backup practical.

    Both are needed: an incremental on its own is only a list of differences. Keep them together and OPBS resolves the chain automatically when you restore.

  2. Schedule it, so nobody has to remember

    Schedules run the same backup unattended — nightly, weekly, whatever suits. A backup you meant to take is worth nothing; a backup that runs at 2am while you are asleep is worth a great deal.

    Close the browser before a backup you might restore in place. A scheduled backup cannot do that for you, so if you rely on schedules, accept that an application's files may come back mid-write — the usual case is a browser profile. See Make your first backup for why.

  3. Set a retention policy, so the disk does not fill up

    Keep the newest few full chains and let OPBS prune the rest. Without it, backups accumulate until the destination is full — and a backup destination that is full silently stops being a backup destination.

  4. Leave verification on

    Verification reads the image back and checks it block by block. It costs time on the day. It is the only thing that tells you a backup is bad before the day you need it.

  5. Check it occasionally

    Open Repositories to see what you have, and prove a restore works now and then. The dashboard's scrub health also tells you when the last integrity scrub ran.

Full or incremental?

Full Incremental
What it captures Everything Only what changed
Size Large Small
Speed Slower Much faster
On its own Restorable Not restorable — it needs its chain
Use it for The first one, and the occasional reset Everything in between

Keep the whole chain together.

An incremental is only useful alongside the images it builds on. Keep them in the same folder, and do not delete the older ones by hand while newer ones depend on them. Retention does this correctly for you.

What this will not save you from

  • A backup on the same disk as the data. If the disk dies, it takes the backup with it.
  • A fire, theft or flood that takes the computer and the backup together. One copy somewhere else is the difference between a bad afternoon and a bad year.
  • Ransomware that encrypts the backup too. An attached external drive is reachable by whatever is running on the machine. Rotate drives, or keep one offline.
  • A backup you have never restored. The rest of this guide is about that one.

Do this today, and then stop thinking about it.

One full backup to a different disk. An incremental schedule. A retention policy. Verification on. That is the whole routine, and it is about fifteen minutes of setup for the thing that decides whether a bad day is survivable.
