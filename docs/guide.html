What OPBS will not do

Tools you trust with your disks should say what they promise. These are invariants — no version of OPBS is allowed to weaken them.

  1. Never write to a disk we cannot identify

    If OPBS cannot resolve exactly which disk and which partitions it is about to change, it stops and says which one it could not resolve. It will not guess, and it will not write to a target it is unsure about.

  2. Never write without showing you the plan first

    Every restore runs a preflight that writes nothing and reports what would happen — where each partition lands, what gets overwritten, what gets cleared. You then type a word to confirm. Nothing is written before that.

  3. Never leave the machine worse than we found it

    A refusal is a success: OPBS turns down restores it cannot prove safe and tells you why, before touching the disk. If something cannot be done safely, the answer is no — not a partial attempt.

  4. Do no work that isn't needed

    A backup that changes nothing does not rewrite anything. A restore that does not need a new partition table does not write one. Work is proportional to the job.

Where these are tested

They are not a promise in a document only. The refusal paths have regression tests, and the free-space clearing — the one mechanism that could destroy data it should not touch — has tests that reconstruct the target from the actual write calls and assert every block the backup contains survives.

What these guides are not

  • Not a substitute for the release notes. New behaviour is described there first.
  • Not a promise that nothing can go wrong. Where OPBS can fail, the guides say so rather than leaving you to find out.
  • Not a support contract. OPBS is free and open source; if you need one, a paid vendor is the right call.
